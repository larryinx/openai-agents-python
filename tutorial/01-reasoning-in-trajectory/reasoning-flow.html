Reasoning 会留在轨迹里吗？

用一个天气查询例子，跟踪模型的 reasoning 从 OpenAI Agents SDK 出发，经过服务器，再被 chat template 渲染成 token 的全过程。切换下方的接入方式、后端和请求序号，看每一层保留了什么、丢掉了什么。

① SDK 层默认保留并原样回传Chat Completions 的 reasoning_content 字段例外
② 服务器层vLLM 通用路径不裁剪OpenAI 看 reasoning.context；gpt-oss 由 vLLM 裁剪
③ 模板层多数模型：回合内保留，跨回合丢弃只渲染最后一条用户消息之后的 reasoning

        可以调节的开关
        
    
        
      
        
        
        Agents SDK
        
        
          
          
        • RunConfig(reasoning_item_id_policy="omit")：保留 reasoning 内容，去掉 rs_... ID。
          • 
          
        • RunConfig(call_model_input_filter=...)：每次请求前自由裁剪输入，例如只保留当前用户回合的 reasoning。
          • 
          
        • OpenAIChatCompletionsModel(..., should_replay_reasoning_content=...)：控制是否回传 reasoning_content。
          • 
          
        • handoff_filters.remove_all_tools：handoff 时连同 reasoning 一起删除。
          • 
          
        • ModelSettings(reasoning=Reasoning(context=...))：OpenAI Responses 上选择 current_turn 或 all_turns。
          • 
        
        
      
        
      
        
        
        vLLM 与模板
        
        
          
          
        • chat_template_kwargs：模板支持时可以改变裁剪策略，例如 Gemma 4 示例模板的 preserve_thinking、DeepSeek V4 的 drop_thinking。
          • 
          
        • --chat-template：换一个模板，就换了一套历史 reasoning 规则。
          • 
          
        • VLLM_ENABLE_RESPONSES_API_STORE=1：才会启用 store；即便开启，非 Harmony 路径用 previous_response_id 回放时也会跳过 reasoning。
          • 
          
        • 带 encrypted_content 的 reasoning item 会被 vLLM 拒绝。
          •
